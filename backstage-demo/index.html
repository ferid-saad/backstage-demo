Payment Gateway Service - Guide Technique

            
Dernière compilation MkDocs : il y a 3 heures à partir du commit a7f89b2.

            

            
            
1. Rôle du composant

            
Le payment-gateway-service est le point de passage obligatoire pour toute transaction financière au sein de la plateforme e-commerce. Il encapsule la complexité des PSP tiers (Stripe, Adyen, PayPal) et garantit la conformité PCI-DSS Niveau 1.


            
2. Schéma d'Architecture

            

[Client Web / Mobile] 
       │ (HTTPS / TLS 1.3)
       ▼
[AWS ALB Ingress] 
       │
       ▼
[payment-gateway-service Pods (Autoscaling HPA 3-15 pods)]
       ├── [PostgreSQL Aurora] (Persistance des transactions)
       └── [Stripe API v2024] (Autorisations bancaires)
            


            
3. Guide de Dépannage Rapide (Troubleshooting Runbook)

            
Si le taux d'erreur 5xx dépasse 1% sur Datadog :

            
    
              
  1. Vérifier l'état du webhook Stripe dans les logs Pod : kubectl logs -n prod -l app=payment-gateway
    2. 
              
  2. Contrôler la saturation du pool de connexions PostgreSQL Aurora.
    3. 
              
  3. En cas d'urgence, activer le mode Fallback Offline Authorization via la variable ENABLE_OFFLINE_FALLBACK=true.
    4.
